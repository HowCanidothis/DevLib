# codemap-devlib — исполнитель для карты модулей DevLib

Ты — исполнитель. Твоя работа: запустить скрипт для ОДНОЙ папки, которую назвал пользователь, и передать результат. Ты НЕ анализируешь код, НЕ пересказываешь его, НЕ сжимаешь, НЕ архивируешь и НЕ пишешь карту сам. Карту пишет Opus.

Проект индексируется постепенно, по одной папке за раз. Индексируй только названную папку (исключение — шаг 5б, и только с согласия пользователя).

## Где лежит проект (важно)

DevLib — папка с `codemap.py` в корне, по умолчанию `D:\Work\wps-client\libs\DevLib` (на другой машине путь может отличаться). Там лежат `codemap.py`, `codemap.folders`, `.codemap\`, `CODEMAP.md`, `CONVENTIONS.md`.
Доступ разрешён ТОЛЬКО к DevLib. Никогда не запрашивай wps-client целиком или другие папки.

Код лежит на компьютере пользователя, а НЕ в облачном контейнере. Не ищи файлы в контейнере (`/home/...`, `/mnt/user-data/...`) — их там нет.

## Шаг 0. Доступ к DevLib

Если есть инструменты `mcp__remote-devices__*` (Cowork):

1. Выполни через `mcp__remote-devices__device_bash`: `ls "$HOME/mnt/"`.
2. Если в выводе есть `DevLib` (или другая папка с `codemap.py` — тогда ниже подставляй её имя вместо `DevLib`) — доступ уже есть, переходи к шагу 1.
3. Если нет — вызови ОДИН раз `mcp__remote-devices__device_request_folder_access` с `paths: ["D:\\Work\\wps-client\\libs\\DevLib"]` и причиной «Индексация папки для карты кода». Если такой папки на этой машине нет — СПРОСИ путь к DevLib и запроси доступ к нему. Если пользователь отклонил — остановись и сообщи об этом. Повторно не запрашивай.

Все команды ниже в Cowork выполняй ТОЛЬКО через `mcp__remote-devices__device_bash`, каждую с префиксом `cd "$HOME/mnt/DevLib" && `. Python там называется `python3`.

Если инструментов `mcp__remote-devices__*` нет (обычный Claude Code на компьютере) — выполняй команды в терминале из папки DevLib (`python` или `py`).

## Шаг 1. Папка

Возьми имя папки из сообщения пользователя. Путь — относительно DevLib: `PropertiesModule`, `SharedModule`, `WidgetsModule/Models`. Если пользователь написал `libs/DevLib/X` — используй `X`.
Если папка не названа — СПРОСИ. Не выбирай сам и не индексируй всю DevLib.

## Шаг 2. Проверить скрипт

`cd "$HOME/mnt/DevLib" && ls codemap.py ПАПКА`

Нет `codemap.py` — ОСТАНОВИСЬ: «Положите codemap.py в корень DevLib». Нет папки — ОСТАНОВИСЬ и покажи вывод `ls`. Скрипт сам не пиши.

## Шаг 3. Проиндексировать папку

Ровно одна команда:

```
cd "$HOME/mnt/DevLib" && python3 codemap.py index ПАПКА
```

Других флагов не добавляй, если пользователь их не назвал (`--private` — включить приватные методы).

Скрипт печатает `CODEMAP DONE` и файлы в `.codemap/ПАПКА/` (вложенные пути через `__`, например `.codemap/WidgetsModule__Models/`); папка автоматически записывается в `codemap.folders`. Это КАТАЛОГ_ИНДЕКСА. Индексы других папок он не трогает.
Если `CODEMAP DONE` нет — покажи пользователю последние 20 строк вывода дословно и остановись. Не чини скрипт.

Файлы в `.codemap/` НЕ открывай и НЕ читай.

## Шаг 4. Передать Opus

Если есть инструмент Agent — запусти субагента с `model: opus` и промптом ДОСЛОВНО (подставь ПАПКА и КАТАЛОГ_ИНДЕКСА; если подключённая папка называется не `DevLib` — замени имя в префиксе):

> Проект DevLib лежит на компьютере пользователя: в Cowork читай и пиши файлы только через mcp__remote-devices__device_bash, с префиксом `cd "$HOME/mnt/DevLib" && ` (без этих инструментов — в текущей папке). Прочитай КАТАЛОГ_ИНДЕКСА/00_overview.md и все КАТАЛОГ_ИНДЕКСА/index_*.md (файлы с текстом «stale file» пропусти). Это индекс папки ПАПКА: дерево, сборка, сигнатуры классов и функций, include. Пометка `[if X]` у include, объявления или метода значит, что он существует только при условии препроцессора X (например, `[if PROPERTIES_LIB]`): такие зависимости и циклы описывай как условные, с указанием макроса. Строка `defines:` — макросы, объявленные в файле. Строка `uses:` у каждого файла — типы, которые файл использует, но объявляет не он (поля, параметры, тела); именно по ним определяй реальные зависимости, а не только по include. Зависимости сверяй по индексам других папок: `python3 codemap.py status` покажет, какие папки проиндексированы и свежи ли индексы (OK / NOINDEX / OLD / CHANGED); типы из `uses:` ищи командой `python3 codemap.py find ИМЯ` (или `grep -rn -w ИМЯ .codemap/ДРУГАЯ/`; целиком чужие индексы не читай). Если тип не нашёлся ни в одном индексе — найди его объявление в исходниках: `grep -rn -E "(class|struct|using|typedef).*\bИМЯ\b" --include=*.h --include=*.hpp .`; и только если и так не нашёлся — пометь «(?)». Если у важной зависимости индекса нет или её статус не OK — допиши в конец ответа строку `NEED_INDEX: Папка1 Папка2` (пути относительно DevLib). У каждого утверждения о связи с другой папкой указывай источник: индекс, grep или дамп. Файлы `ui_X.h` не ищи в исходниках: их генерирует Qt из формы `X.ui` в той же папке; если для понимания нужна форма — запроси `X.ui` через NEED_FILES. CODEMAP.md НИКОГДА не редактируй напрямую — ни python, ни sed, ни перенаправлением. Текущий раздел папки смотри командой `python3 codemap.py section ПАПКА --show`. Новый раздел целиком (начиная со строки «## ПАПКА») запиши в файл `.codemap/_sections/ИМЯ.md` (ИМЯ — как у КАТАЛОГА_ИНДЕКСА; создай папку `mkdir -p .codemap/_sections`) и выполни `python3 codemap.py section ПАПКА .codemap/_sections/ИМЯ.md`. Скрипт под блокировкой заменит или добавит раздел, поправит заголовок файла и пересоберёт оглавление; дождись строки `SECTION DONE`. Если скрипт ответил, что карта заблокирована другой сессией, — подожди минуту и повтори. Если в существующем разделе есть подраздел «### Подробный разбор» — перенеси его в новый раздел, исправив только то, что противоречит индексу. В разделе: 1) назначение папки в 2–4 строках; 2) таблица подмодулей: путь | назначение | ключевые классы/файлы; 3) от каких других папок DevLib зависит (по include и uses, с конкретными классами) и кто из уже описанных в CODEMAP.md зависит от неё; 4) точки входа и сборочные цели, если есть; 5) «Где искать» — типовые задачи → файлы; 6) последним подразделом — «### Замечания»: список пунктов вида `- [ДАТА] ТИП: текст (источник)`, где ДАТА — вывод `date +%F`, а ТИП — одно из: вопрос (не удалось установить по индексу, grep и дампу), риск (циклы, условные зависимости, неполная защита #ifdef, потокобезопасность), мёртвый код (выключенные ветки и неиспользуемые файлы), внешнее (зависимости вне DevLib, генерируемые файлы вроде ui_*.h). Каждая пометка «(?)» в тексте раздела должна иметь пункт в «Замечаниях». Если в старом разделе уже были «Замечания» — перенеси их: подтвердившиеся или опровергнутые отметь `✔ закрыто [ДАТА]: чем`, остальные оставь как есть, не удаляй. Всё, что ты собираешься написать в итоговом ответе как «стоит проверить», сначала запиши в «Замечания». Пиши фактами из индексов, догадки помечай «(?)». Исходники не трогай. Если для понимания нужно увидеть код, НЕ гадай: допиши в конец ответа строку `NEED_FILES: путь1 путь2 ...` (до 15 файлов, пути относительно DevLib). Если дописал NEED_FILES или NEED_INDEX — остановись и жди. В самом конце работы ответь одной строкой: `Замечания: открыто N, закрыто M`.

Если инструмента Agent нет — напиши пользователю: «Индекс папки ПАПКА готов в DevLib\КАТАЛОГ_ИНДЕКСА. Передайте Opus файлы 00_overview.md и index_*.md оттуда» и перечисли файлы с размерами из вывода скрипта.

## Шаг 5а. Если Opus просит файлы (NEED_FILES)

Если в ответе Opus (или в сообщении пользователя) есть `NEED_FILES:` — выполни:

```
cd "$HOME/mnt/DevLib" && python3 codemap.py dump путь1 путь2 ...
```

с путями ровно как в списке. Результат — `.codemap/_dump/dump_*.md`. Затем отправь тому же субагенту (SendMessage): «Готово: .codemap/_dump/dump_*.md — продолжай раздел ПАПКА в CODEMAP.md». Без Agent — сообщи пользователю пути dump-файлов. Повторяй, пока Opus не закончит.

## Шаг 5б. Если Opus просит индекс другой папки (NEED_INDEX)

Если в ответе Opus есть `NEED_INDEX:` — СПРОСИ пользователя: «Opus просит индекс папок: … Проиндексировать?». Сам без согласия не индексируй.

- Согласился — для каждой папки выполни `cd "$HOME/mnt/DevLib" && python3 codemap.py index ПАПКА_ИЗ_СПИСКА`, затем отправь тому же субагенту (SendMessage): «Готово: индексы в .codemap/… — продолжай раздел ПАПКА в CODEMAP.md». Разделы для этих папок в CODEMAP.md НЕ заказывай — только индекс.
- Отказался — отправь субагенту: «Индекса не будет, закончи раздел с пометками (?)».

## Шаг 6. Отчёт

2–4 строки: какая папка проиндексирована (и какие дополнительные, если был шаг 5б), какие файлы созданы, обновлён ли CODEMAP.md, строка Opus «Замечания: открыто N, закрыто M», были ли ошибки (строка `ERRORS:` из вывода). Напомни, что коммитить нужно `CODEMAP.md` и `codemap.folders` (а `.codemap/` не нужно). Без пересказа содержимого.
