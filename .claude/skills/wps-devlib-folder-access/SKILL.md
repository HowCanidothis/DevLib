# Доступ к DevLib, поиск по карте кода и соглашения

## Доступ

DevLib — папка с `codemap.py` в корне, по умолчанию `D:\Work\wps-client\libs\DevLib` (на другой машине путь может отличаться). В Cowork подключённая папка видна как `$HOME/mnt/DevLib` (по имени папки).

1. Сначала `ls "$HOME/mnt/"` — если там есть `DevLib` (или другая папка с `codemap.py` — тогда ниже подставляй её имя вместо `DevLib`), доступ не запрашивай.
2. Иначе вызови `device_request_folder_access` один раз для `D:\Work\wps-client\libs\DevLib` с короткой причиной на русском. Если такой папки на этой машине нет — спроси у пользователя путь к DevLib и запроси его. Запрашивай только DevLib, не корень wps-client.
3. Если нужен файл вне DevLib, сначала спроси пользователя, стоит ли расширять доступ, и не запрашивай его сам.
4. Если пользователь отклонил запрос, не повторяй его. Предложи альтернативы: подключить папку через кнопку «Add folder» в приложении, прикрепить файлы или вставить фрагменты кода.
5. Индексация и обновление карты — только через скиллы `codemap-devlib` и `codemap-devlib-update`. Исключение: если `python3 codemap.py find` пишет, что индексов нет, или `python3 codemap.py status` показывает `NOINDEX`/`OLD` (свежий клон или новая версия скрипта) — можно сразу выполнить `python3 codemap.py reindex`: это бесплатно, без ИИ, и меняет только `.codemap/`. В остальном этот скилл только читает карту, индексы и соглашения.

## Где искать (важно)

Источник правды — папка DevLib НА КОМПЬЮТЕРЕ пользователя: в Cowork — `mcp__remote-devices__device_bash` с префиксом `cd "$HOME/mnt/DevLib" && `, Python — `python3`. Копии в облачном контейнере (`/mnt/user-data/uploads/...`) — это частичная выборка отдельных файлов. Искать по ним классы НЕЛЬЗЯ: чего нет в выборке, может быть в DevLib. Вывод «такого класса нет» делай только после шагов 1–3 ниже.

В корне DevLib:
- `CONVENTIONS.md` — соглашения по коду (единственный источник правил): выбор механизма, LocalProperty, вычисления, потоки, подписки, сериализация, UI, сборка, известные ошибки, чеклист. Читай нужный раздел: `python3 codemap.py section РАЗДЕЛ --show --file CONVENTIONS.md` (список разделов — `section ? --show --file CONVENTIONS.md`).
- `CODEMAP.md` — карта: по разделу `## Модуль` на модуль (назначение, подмодули, зависимости, «Где искать», «Замечания»). Файл большой — читай нужный раздел: `python3 codemap.py section МОДУЛЬ --show`.
- `codemap.folders` — список проиндексированных папок (в git).
- `.codemap/МОДУЛЬ/` — индекс модуля (генерируется, в git не хранится): классы, сигнатуры, `inc:`, `uses:` (какие чужие типы использует файл), `alias` (typedef/using), `defines:`, пометки `[if X]` (существует только при макросе X). Вложенные папки — через `__` (`.codemap/WidgetsModule__Models/`).
- `.codemap/_dump/` — выгрузки исходников по запросу. Это не полный код.

## Как искать класс, функцию или тип

1. **Одна команда:** `cd "$HOME/mnt/DevLib" && python3 codemap.py find ИМЯ` — покажет, где ИМЯ объявлено (файл), где реализовано (.cpp и список методов), сигнатуры с ним, какие файлы его используют и строки CODEMAP.md с упоминанием.
2. **Не нашлось в индексах** (скрипт пишет `NOT FOUND`) — модуль мог ещё не быть проиндексирован: `grep -rn -w "ИМЯ" --include=*.h --include=*.hpp --include=*.cpp .` по исходникам DevLib.
3. **Не нашлось и там** — тогда можно сказать, что в DevLib его нет (возможно, он в остальном wps-client, куда доступа нет). `ui_X.h` не ищи — его генерирует Qt из `X.ui`.
4. Исходник читай точечно — только файлы, найденные на шагах 1–2.

Когда вопрос про модуль целиком: сначала `python3 codemap.py section МОДУЛЬ --show`, затем при необходимости индекс `.codemap/МОДУЛЬ/`. Не подменяй модуль: индекс `SharedModule` не отвечает на вопрос про `PropertiesModule`. Если раздела и индекса нет — скажи об этом и предложи `/codemap-devlib МОДУЛЬ`.

## Перед написанием или ревью кода

Прочитай разделы `CONVENTIONS.md` по теме задачи и всегда «Известные ошибки» и «Чеклист перед коммитом». Правила из скиллов `wps-properties-*` и `wps-devlib-ui-patterns` — отсылки сюда; при расхождении прав `CONVENTIONS.md`. После кода пройди по чеклисту.

В ответе указывай источник (карта, индекс, соглашения, grep или исходник). Индекс и карта могут отставать от кода; если пишешь код по сигнатурам — сверь их с исходником.

## Субагенты (обязательно)

Субагент не видит этот скилл. Если поручаешь субагенту (например, Opus в режиме team) что-то про код DevLib, добавь в его промпт дословно (если подключённая папка называется не `DevLib` — замени имя в префиксе):

> Код DevLib лежит на компьютере пользователя: в Cowork работай через mcp__remote-devices__device_bash с префиксом `cd "$HOME/mnt/DevLib" && `. Файлы в /mnt/user-data/uploads — неполная выборка, не делай по ним вывод «нет такого класса». Любой класс, функцию или тип ищи так: 1) `python3 codemap.py find ИМЯ` (объявление, реализация, использование, строки карты); 2) если NOT FOUND — `grep -rn -w "ИМЯ" --include=*.h --include=*.hpp --include=*.cpp .`; 3) только потом читай найденные файлы. Обзор модуля: `python3 codemap.py section МОДУЛЬ --show`. Код обязан соответствовать `CONVENTIONS.md`: разделы читай `python3 codemap.py section РАЗДЕЛ --show --file CONVENTIONS.md`, в конце пройди «Чеклист перед коммитом». CODEMAP.md, CONVENTIONS.md и .codemap не редактируй.

## Пример

Запрос «собери форму через WidgetBuilder»: `python3 codemap.py find WidgetBuilder` → объявлен в `WidgetsModule/Utils/widgetbuilder.h`, методы в `widgetbuilder.cpp`, карта — раздел `## WidgetsModule`. Затем `section "UI: окна и WidgetBuilder" --show --file CONVENTIONS.md`, прочитать `widgetbuilder.h` для точных сигнатур и писать код.
