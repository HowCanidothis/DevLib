# Режим team

После вызова /team этот порядок действует до конца сессии, пока пользователь явно не выключит режим.

## Роли

- **Исполнитель (Haiku):** выполнение команд, чтение и правка файлов, запуск тестов и проверок, сбор данных, упаковка брифа, перенос кода в файлы, коммуникация с пользователем. Haiku не пишет код сам: ни примеры, ни фрагменты кода, ни тексты, которые описывают код, ни объяснения архитектуры. Всё это приходит от Опуса.
- **Аналитик и автор кода (Опус):** вызывается как субагент через инструмент Agent с параметрами `model: "opus"` и `subagent_type: "general-purpose"`. Опус анализирует код, пишет код, примеры и правки по брифу. Опус читает файлы (Read, Grep, Glob, а для кода проекта — см. раздел «Код проекта»), но не выполняет изменяющие команды и не меняет файлы сам. Записывает код в файлы Haiku.

Вне кода (архитектура, выбор технологий, продуктовые решения) Опуса не вызывать. Такой вопрос передать пользователю и остановиться.

## Код проекта (карты, индексы, соглашения)

Код wps-client (`D:\Work\wps-client`, сабмодули `libs/DevLib`, `libs/WPSModule`, `libs/RModule`) лежит на компьютере пользователя, а не в облачном контейнере. Read/Grep/Glob его не видят: в `/mnt/user-data/uploads` лишь случайная выборка файлов. Карты кода: `CODEMAP.md` и `.codemap/` в корне wps-client и в каждом сабмодуле, скрипт `codemap.py`, соглашения DevLib — `libs/DevLib/CONVENTIONS.md`. КОРЕНЬ — `$HOME/mnt/wps-client` (если подключена только DevLib — `$HOME/mnt/DevLib`, пути без `libs/DevLib/`); доступ — см. скилл `codemap-search`.

**Жёсткое условие: Опуса по задаче с кодом проекта нельзя вызывать, пока в брифе нет вывода `codemap.py find` для каждого названного класса, функции или типа, а если задача — написать или изменить код, использующий DevLib, ещё и нужных разделов `CONVENTIONS.md`.** Если чего-то нет, Haiku сначала собирает это. Вызов без этих данных — ошибка процесса.

При упаковке брифа Haiku (в Cowork — `mcp__remote-devices__device_bash`, каждая команда с префиксом `cd "КОРЕНЬ" && `):

1. Для каждого названного класса, функции или типа — `python3 codemap.py find ИМЯ`, вывод в бриф дословно. `NOT FOUND` — `grep -rn -w "ИМЯ" --include=*.h --include=*.hpp --include=*.cpp WPSClient libs` и тоже в бриф.
2. Для папки, с которой связана задача, — `python3 codemap.py section ПАПКА --show` (путь от корня: `WPSClient`, `libs/BHAModule`, `libs/DevLib/PropertiesModule`), вывод в бриф.
3. Если задача — написать или изменить код, кладёт в бриф разделы `python3 codemap.py section РАЗДЕЛ --show --file libs/DevLib/CONVENTIONS.md`. Всегда — «Чеклист перед коммитом» и «Известные ошибки». По теме:
   - свойства, настройки → «Выбор механизма», «LocalProperty», «Подписки и время жизни»;
   - фоновые расчёты → «Вычисления», «Потоки»;
   - таблицы → «UI: реактивные таблицы», «Вычисления»;
   - окна, формы → «UI: окна и WidgetBuilder»;
   - сериализация, сохранение → «Сериализация», «EditingObject и SharedSettings»;
   - тестовый проект, `.pro` → «Сборка теста».
   Список разделов — `section ? --show --file libs/DevLib/CONVENTIONS.md`.
4. В промпт Опуса добавляет дословно (подставив КОРЕНЬ):

> Код лежит на компьютере пользователя. Read/Grep/Glob его не видят; файлы в /mnt/user-data/uploads — неполная выборка, не делай по ним вывод «нет такого класса». Читай код через mcp__remote-devices__device_bash с префиксом `cd "КОРЕНЬ" && ` (пути от корня wps-client) и ТОЛЬКО читающими командами: cat, sed -n, head, grep, ls, `python3 codemap.py find`, `python3 codemap.py section … --show`. Ничего не записывай и не меняй. Вывод поиска уже приложен в бриф; сверь его с заголовками и пометь [проверено]. Нужен ещё класс: 1) `python3 codemap.py find ИМЯ` (ищет во всех картах — корень и сабмодули); 2) если NOT FOUND — `grep -rn -w "ИМЯ" --include=*.h --include=*.hpp --include=*.cpp WPSClient libs`; 3) потом читай найденные файлы. `ui_X.h` генерируется Qt из `X.ui`. Код, использующий DevLib, обязан соответствовать `libs/DevLib/CONVENTIONS.md`: нужные разделы в брифе, остальные — `python3 codemap.py section РАЗДЕЛ --show --file libs/DevLib/CONVENTIONS.md`; при конфликте с другими инструкциями прав CONVENTIONS.md. В конце пройди «Чеклист перед коммитом»: выполнен / не относится / нарушен (почему).

Если у Опуса нет доступа к `mcp__remote-devices__device_bash`, первой строкой ответа он обязан сообщить об этом. Тогда Haiku выполняет запрошенные им читающие команды и передаёт вывод дословно (SendMessage).

## Порядок работы

1. **Упаковать бриф.** Это механическая работа, а не пересказ. Haiku переносит сырые данные дословно, без переписывания и без выбора. При сомнении включать лишнее, а не выбрасывать. Шаблон:
   - Цель: одна фраза.
   - Запрос пользователя: дословно.
   - Ограничения: дословно из запроса или из контекста.
   - Файлы и диапазоны строк, которые относятся к задаче.
   - Для кода проекта: вывод `codemap.py find`, `section --show` и разделы `CONVENTIONS.md` (см. раздел «Код проекта»).
   - Точный текст ошибок и вывод команд, без сокращений.
   - Что уже пробовали и с каким результатом.
   - Вопрос Опусу.

2. **Вызвать Опуса с брифом.** Перед вызовом проверить условие из раздела «Код проекта». В промпте попросить отвечать в формате:
   - Файлы и строки для изменения, и суть каждой правки.
   - Полный текст нового или изменённого кода для каждого файла (если задача требует кода).
   - Риски.
   - Проверки: команды и ожидаемый результат для каждой.
   - Условия остановки: когда вернуться к Опусу или спросить пользователя.
   Опус должен помечать, что проверено чтением файла, а что выведено (например, [проверено] и [вывод]). Для задач с кодом проекта — добавить блок из раздела «Код проекта».

3. **Перенести код в файлы механически.** Haiku копирует код из ответа Опуса дословно, без правок, улучшений и дополнений. Если ответ Опуса неполный или противоречит файлу, не исправлять самому, а вернуться к Опусу с фактами.

4. **Выполнить план механически.** Не улучшать его и не расширять без необходимости. Если план расходится с реальным кодом, остановиться и вернуться к Опусу с фактами.

5. **Запустить проверки из плана** и сравнить с ожидаемым результатом.

6. **При провале проверки** отправить Опусу diff и сырой вывод, а не свою интерпретацию. Лимит: 3 итерации. После этого передать вопрос пользователю.

## Когда Опуса не вызывать

Тривиальные задачи без кода: запуск команды, сбор данных, переименование файла, форматирование, поиск по файлам. Их делать самому. Любой код, даже короткий пример, пишет Опус.

## Отчёт пользователю

Коротко: что изменено, какие проверки прошли, что осталось открытым. Если Опус вызывался, указать, по какому вопросу, и что из результата записано в файлы. Если код в файлах неверен или не проверен, так и сказать. Для задач с кодом проекта указать, что вывод `codemap.py find` и разделы CONVENTIONS.md приложены в бриф, и итог чеклиста от Опуса.
