# codemap — индексировать папку и описать её в карте кода

Ты — исполнитель. Запускаешь скрипт для ОДНОЙ папки, которую назвал пользователь, и передаёшь результат Opus. Ты НЕ анализируешь код, НЕ пересказываешь, НЕ сжимаешь и НЕ пишешь карту сам. Карту пишет Opus.

## Как устроены карты

- Проект с файлом `codemap.conf` — отдельная карта: свои `CODEMAP.md`, `codemap.folders`, `.codemap/`.
- Сабмодули `libs/DevLib`, `libs/WPSModule`, `libs/RModule` — карты в git. Корень wps-client — локальная карта (в git не попадает, см. `.git/info/exclude`).
- Все команды запускаются ИЗ КОРНЯ, пути — от корня (`WPSClient`, `libs/BHAModule`, `libs/DevLib/PropertiesModule`). Скрипт сам определяет, в чью карту писать.
- DevLib и уже настроенные проекты индексируются по папкам. Маленький сабмодуль (WPSModule, RModule) — целиком: `index libs/WPSModule`.

## Шаг 0. Корень и доступ

В Cowork: `mcp__remote-devices__device_bash`, команда `ls "$HOME/mnt/"`.
- есть `wps-client` → КОРЕНЬ = `$HOME/mnt/wps-client`;
- есть только `DevLib` → КОРЕНЬ = `$HOME/mnt/DevLib` (доступна только DevLib, пути без `libs/DevLib/`);
- нет ни того, ни другого → ОДИН раз `mcp__remote-devices__device_request_folder_access` для `D:\Work\wps-client` с причиной «Карта кода проекта». Если такой папки на этой машине нет — СПРОСИ путь к wps-client. Отказ — остановись.

Все команды ниже — через `mcp__remote-devices__device_bash` с префиксом `cd "КОРЕНЬ" && `, Python — `python3`. Без инструментов `mcp__remote-devices__*` — терминал в корне проекта (`python` или `py`). Код лежит на компьютере пользователя, НЕ в облачном контейнере — не ищи его в `/home/...` или `/mnt/user-data/...`.

## Шаг 1. Папка

Возьми папку из сообщения пользователя, путь от корня. Если папка не названа — СПРОСИ. Не выбирай сам и не индексируй весь проект.

## Шаг 2. Скрипт

`ls codemap.py ПАПКА`.
- Нет папки — ОСТАНОВИСЬ и покажи вывод.
- Нет `codemap.py`, но есть `libs/DevLib/codemap.py` — корневая карта на этой машине не настроена: выполни раздел «Настройка корня» ниже и вернись сюда.
- Нет ни того, ни другого — ОСТАНОВИСЬ.

## Шаг 3. Индексировать

Ровно одна команда: `python3 codemap.py index ПАПКА` (флаг `--private` — только если пользователь попросил).

Скрипт печатает `CODEMAP DONE` и пути файлов индекса, например `libs/DevLib/.codemap/PropertiesModule/00_overview.md` или `.codemap/WPSClient/00_overview.md`. Папка этих файлов — КАТАЛОГ_ИНДЕКСА. Строка `(project X: ...)` значит, что папка принадлежит сабмодулю X и попадёт в его карту. Нет `CODEMAP DONE` — покажи последние 20 строк вывода и остановись. Скрипт не чини. Файлы индекса сам НЕ читай.

## Шаг 4. Передать Opus

Если есть инструмент Agent — запусти субагента `model: opus` с промптом ДОСЛОВНО (подставь КОРЕНЬ, ПАПКА, КАТАЛОГ_ИНДЕКСА):

> Проект лежит на компьютере пользователя: в Cowork читай и пиши файлы только через mcp__remote-devices__device_bash с префиксом `cd "КОРЕНЬ" && ` (без этих инструментов — в корне проекта в терминале). Все пути — от корня. Прочитай КАТАЛОГ_ИНДЕКСА/00_overview.md и все КАТАЛОГ_ИНДЕКСА/index_*.md (файлы с текстом «stale file» пропусти). Это индекс папки ПАПКА: дерево, сборка, сигнатуры классов и функций, include. Пометка `[if X]` значит, что include, объявление или метод существуют только при макросе X: такие зависимости описывай как условные. `defines:` — макросы файла. `uses:` — типы, которые файл использует, но объявляет не он; по ним определяй реальные зависимости. Проект состоит из нескольких карт: сабмодули (libs/DevLib, libs/WPSModule, libs/RModule) и корень wps-client. `python3 codemap.py status` покажет все проиндексированные папки и свежесть индексов; `python3 codemap.py find ИМЯ` ищет тип во ВСЕХ картах и показывает, в каком проекте он объявлен (целиком чужие индексы не читай). Если тип не найден — `grep -rn -E "(class|struct|using|typedef).*\bИМЯ\b" --include=*.h --include=*.hpp .`; не нашёлся и так — помечай «(?)». Если у важной зависимости нет индекса или статус не OK — допиши в конец ответа `NEED_INDEX: Папка1 Папка2` (пути от корня). У каждого утверждения о связи с другой папкой указывай источник: индекс, grep или дамп. `ui_X.h` генерирует Qt из `X.ui` в той же папке; нужна форма — запроси `X.ui` через NEED_FILES. Карты НИКОГДА не редактируй напрямую. Текущий раздел: `python3 codemap.py section ПАПКА --show`. Новый раздел целиком (начиная со строки «## ЗАГОЛОВОК», где ЗАГОЛОВОК — имя, которое показал --show, или ПАПКА без пути сабмодуля) запиши в `.codemap/_sections/ИМЯ.md` (`mkdir -p .codemap/_sections`) и выполни `python3 codemap.py section ПАПКА .codemap/_sections/ИМЯ.md`; скрипт сам запишет его в нужную карту под блокировкой, дождись `SECTION DONE`. Карта заблокирована другой сессией — подожди минуту и повтори. Подраздел «### Подробный разбор» старого раздела перенеси, исправив только то, что противоречит индексу. В разделе: 1) назначение папки в 2–4 строках; 2) таблица подмодулей: путь | назначение | ключевые классы/файлы; 3) зависимости от других папок и проектов (по include и uses, с конкретными классами; для сабмодулей — в какой проект ведёт связь) и кто из уже описанных зависит от неё; библиотека не должна описывать своих пользователей из других проектов; 4) точки входа и сборочные цели; 5) «Где искать» — типовые задачи → файлы; 6) последним — «### Замечания»: пункты `- [ДАТА] ТИП: текст (источник)`, ДАТА — вывод `date +%F`, ТИП — вопрос, риск, мёртвый код или внешнее. Каждая пометка «(?)» должна иметь пункт в «Замечаниях». Старые «Замечания» перенеси: подтвердившиеся или опровергнутые отметь `✔ закрыто [ДАТА]: чем`, остальные оставь. Всё, что хочешь написать как «стоит проверить», сначала запиши в «Замечания». Пиши фактами, догадки помечай «(?)». Исходники не трогай. Нужно увидеть код — НЕ гадай: допиши `NEED_FILES: путь1 путь2 ...` (до 15 файлов, пути от корня). Если дописал NEED_FILES или NEED_INDEX — остановись и жди. В самом конце ответь одной строкой: `Замечания: открыто N, закрыто M`.

Без Agent — напиши пользователю: «Индекс папки ПАПКА готов в КАТАЛОГ_ИНДЕКСА, передайте Opus 00_overview.md и index_*.md» и перечисли файлы с размерами.

## Шаг 5а. NEED_FILES

`python3 codemap.py dump путь1 путь2 ...` (пути как в списке) → `.codemap/_dump/dump_*.md`. Затем SendMessage тому же субагенту: «Готово: .codemap/_dump/dump_*.md — продолжай раздел ПАПКА». Повторяй, пока Opus не закончит.

## Шаг 5б. NEED_INDEX

СПРОСИ пользователя: «Opus просит индекс папок: … Проиндексировать?».
- Да — для каждой `python3 codemap.py index ПАПКА_ИЗ_СПИСКА`, затем SendMessage: «Готово: индексы … — продолжай раздел ПАПКА». Разделы для этих папок НЕ заказывай.
- Нет — SendMessage: «Индекса не будет, закончи раздел с пометками (?)».

## Шаг 6. Отчёт

2–4 строки: какая папка проиндексирована (и какие ещё — шаг 5б), в какую карту записан раздел, строка Opus «Замечания: …», ошибки (строка `ERRORS:`). Напомни, что коммитить: для сабмодуля — его `CODEMAP.md` и `codemap.folders`; карта корня wps-client локальная, её не коммитят.

## Настройка корня (новая машина, нет `codemap.py` в корне wps-client)

1. Создай `codemap.conf` в корне (heredoc через `cat > codemap.conf`):
```
# Local codemap of wps-client (not in git: listed in .git/info/exclude).
name = wps-client
script = libs/DevLib
links = libs/DevLib libs/WPSModule libs/RModule
exclude = bin_* build build-* debugmsvc Builds Installer* */debug */release */x64
exclude = Proj/Proj/proj libs/Content libs/AdditionalResources
exclude = libs/Eigen libs/alglib libs/Ceres libs/Exprtk libs/ExprtkModule/exprtk.hpp libs/GeographicLib
exclude = libs/QXlsx libs/Qt-Ads-Custom libs/quazip libs/BasicExcel libs/Cells libs/LexLicense
exclude = libs/ProjModule/include libs/ProjModule/proj libs/AWSLibModule/include libs/MongoDBModule/include
exclude = libs/*/lib
```
   В `links` оставь только те сабмодули, где есть `codemap.conf`.
2. `python3 libs/DevLib/codemap.py sync` — копирует скрипт в корень и в сабмодули.
3. Если в `.git/info/exclude` нет строки `/codemap.py` — допиши туда строки `/codemap.py`, `/codemap.conf`, `/codemap.folders`, `/CODEMAP.md`, `/.codemap/`. Не удаётся записать — скажи пользователю добавить их вручную.
4. Карта корня на новой машине пустая: папки добавляются через `/codemap ПАПКА`.

## Запрещено

- запрашивать доступ к чему-либо кроме папки wps-client (или DevLib, если подключена только она);
- индексировать что-либо кроме названной папки без согласия пользователя (шаг 5б);
- индексировать весь проект целиком (кроме маленьких сабмодулей WPSModule, RModule);
- читать исходники или `.codemap/` и делать по ним выводы; писать карты самому;
- сжимать, архивировать, кодировать в base64;
- менять codemap.py или код проекта; удалять что-либо;
- запускать что-то кроме команд из шагов 2, 3, 5а, 5б и «Настройки корня».
